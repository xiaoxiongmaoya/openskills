# 工作目录规范（冻结，中文目录）

本文件定义**目录与文件归位规则**。开工前先读，按此执行，不要临时新建目录。

## 1. 三层边界

| 层 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| Skill 层 | `~/.workbuddy/skills/court-civil-first-instance-filing/` | **只读** | 代码、references。禁止写入任何运行产物 |
| 工作空间根 | 用户在 WorkBuddy 里选的文件夹 | 读写 | 只放 `案件库/`、`通用件/`，不散放文件 |
| 案件目录 | `<根>/案件库/<案件标识>/` | 读写 | 一案一目录，全部产物在此 |

**硬规则：session、验证码、日志、spec、解压件、js 缓存一律不许落在 skill 目录或工作空间根。**
违反会导致跨案污染：登录态串号、验证码与新 id 错配、状态文件互相覆盖。

## 2. 案件目录骨架

```
<根>/
├── 案件库/
│   └── 20260101-0000-张三诉李四-民间借贷/
│       ├── 01原始包/      客户 zip/rar 原样 + `解压/` 展开结果（只读，不上传）
│       ├── 02签字件/      已签字/盖章的 PDF —— 直接上传的那批
│       ├── 03图片件/      身份证、借条、聊天截图（jpg/png）
│       ├── 04未签稿/      Word 文档 + 尚未签字的 PDF
│       ├── 05案件信息/    case.json / spec.json / draft.json / 提交结果
│       ├── 06运行记录/    会话文件、验证码截图、运行日志（敏感，勿外发）
│       └── 案件说明.md
├── 通用件/                 律所函、空白授权书等每个案子复用的件
└── .workbuddy/
```

目录名：`{YYYYMMDD}-{fyid}-{原告}诉{被告}-{案由}`。日期用建案日，建后不改（改名会让脚本里的绝对路径失效）。重建同案不新建目录（幂等）。

**分类逻辑**（`organize_materials.py` 自动执行，不靠临场判断）：

- 已签字 PDF → `02签字件`（上传件收件箱）
- jpg/png → `03图片件`
- doc/docx/wps、未签 PDF → `04未签稿`（待签待办区）
- **Word 原稿必须保留在 `04未签稿/`，即使已有签字 PDF**：所有文书信息只从 Word 解析，PDF 不解析（扫描件 OCR 会把 200000 读成 20000）。

材料命名统一 `序号-材料名-页序.ext`，序号对齐法院槽位：
`01-起诉状-1.pdf`、`01-起诉状-2.pdf`、`02-原告身份证.jpg`、`03-授权委托书.pdf`、`03-律师事务所函.pdf`、`03-律师执业证.pdf`、`04-借条.jpg`、`05-送达地址确认书.pdf`、`06-账户确认书.pdf`。
上传法院时直接用这套文件名，前台就不会显示一串 uuid。**代理律师立案必须有律师执业证**。

## 3. 乱压缩包处理（固定动作）

1. **中文转码**：Windows 打的包文件名多为 GBK，Python 默认按 cp437 解，必须按 zip 头自行转码，否则全变乱码（实测踩过）。
2. **解压只往 `01原始包/解压/`**，保留原始层级，便于回溯。
3. **分类是复制，不是移动**；原件保留，不删不改名。
4. 同名 `.docx` + `.pdf`（如账户确认书）：PDF 进 02，docx 进 04，不许混层。
5. 未能识别的文件列在 `unrecognized` 里，人工归位后重跑（幂等，已存在不覆盖）。

## 4. 文件归位表

| 产物 | 位置 |
| --- | --- |
| 客户压缩包 | `01原始包/` |
| 解压结果 | `01原始包/解压/` |
| 上传用签字 PDF | `02签字件/` |
| 身份证/证据图片 | `03图片件/` |
| Word、未签 PDF | `04未签稿/` |
| case.json / spec.json / draft.json / submit_result.json | `05案件信息/` |
| 立案单状态快照 `立案单状态.json` | `05案件信息/` |
| **法院退回的附件**（模板、补正材料） | `05案件信息/法院退回件/`（`query_filing.py --write` 自动下载，文件名用法院原文） |
| **人看的运行结果** `案件说明.md` | 案件目录根，`write_case_note.py` 自动生成 |
| 会话 `.court_session.json`、验证码 `captcha.png` | `<根>/通用件/.court_session.json`（共享）、`06运行记录/captcha.png` |
| 案由树缓存 `ay_tree_0300.json` | `05案件信息/cache/` |
| 耗时埋点 `timing.jsonl` | `06运行记录/` |
| 运行日志、`状态变更.log` | `06运行记录/YYYY-MM-DD.log`（脱敏） |

`case.json` 关键字段：`filing_id`（当前有效的 layy id，提交后不变）、`previous_filing_ids`（被替代的旧单，留档）、`status` / `status_code` / `submitted_at` / `case_no` / `review_opinion` / `last_checked_at`、`decisions`（两项闸门的值 + 时间戳）。

## 5. 会话隔离（已改为共享一份）

- **登录态是账号级的，不是案件级的**：统一存 `<工作空间根>/通用件/.court_session.json`（`court_client.session_file_for()` 自动算；可用环境变量 `COURT_SESSION_FILE` 覆盖）。
- token 有效期 1 小时：同一小时内的多个案子复用同一份会话，只登录一次、只过一次验证码。
- 写入是原子的（临时文件 + `os.replace`）；遇到 401/403 只清本进程内存，**不删共享文件**——否则一个 worker 失败会把其他人一起登出。
- 确需隔离（换账号/换法院）时显式传别的 `--session-file`，或删掉共享会话文件重新登录。
- 运行产物仍不许落 skill 目录与工作空间根：`06运行记录/` 放验证码、日志、`timing.jsonl`；`05案件信息/cache/` 放案由树等缓存。

## 6. 两项必问闸门（提交前，缺一即中止）

| 决策 | 取值 | 落库位置 |
| --- | --- | --- |
| 是否同意先行调解 | `decisions.mediation` = yes/no | `layy.lasfzsqt` + `05案件信息/case.json` |
| 是否上传被告身份证照片 | `decisions.defendant_id_photo` = upload/skip | `05案件信息/case.json`（照片本身不落库） |

- **身份信息（证件号）可以照填，照片必须单独确认**，两者不可合并成一个问题。
- spec 里两字段默认 `null`；`null` 一律视为未定，脚本不得替用户猜。
- 决策连同时间戳写入 `case.json`，事后可追溯谁定的、什么时候定的。

## 6.5 多原告 / 多被告

- `spec.json` 用列表字段：`plaintiffs: [ {当事人1}, {当事人2} ]`、`defendants: [ {当事人1}, {当事人2} ]`
- 只有一个当事人时仍可用单数 `plaintiff` / `defendant`（历史案件兼容，无需改）
- `bootstrap_case.py` 的 `--plaintiff` / `--defendant` 支持用 `、` 或 `,` 分隔多个姓名，自动写成列表
- 目录名与 `ajmc` 取**首个被告**；参与人展示串 `dsrMc` 包含全部当事人（`原告：A；被告：B，C`）

## 7. 初始化

```bash
# 1. 建案件目录
python scripts/bootstrap_case.py --root "<工作空间根>" \
  --fyid 0000 --court "某某市某某区人民法院" --region 000000 \
  --cause "民间借贷纠纷" --plaintiff "张三" --defendant "李四"

# 2. 整理客户材料（可先 --dry-run 看映射）
python scripts/organize_materials.py --case-dir "<案件目录>" --source "<zip 或 乱目录>"
```

## 8. 禁止事项

- 禁止在 skill 目录、工作空间根、桌面根写运行产物。
- 禁止改名或删除 `01原始包/` 里的原始件。
- 禁止多个案件共用一个 `draft.json` / `case.json`。
- 禁止把含身份证号/手机号的 `case.json`、`spec.json` 进仓库或外发。
