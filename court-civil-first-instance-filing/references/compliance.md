# 合规与运行红线

## 1. 凭证与授权

- 只操作用户本人已授权的法院账号；代操作前必须取得用户明确授权。
- 凭证（账号/密码/token/cookie）加密存储（KMS 信封加密或本机加密容器），不明文落库。
- 凭证仅用于登录与本人的立案/案件查询，不用于任何其他目的。
- 分发打包前必须清除：API Key、密码、Cookie、token、测试账号。打包脚本只放代码与文档。

## 2. 验证码

- 双轨制：OCR 自动识别 + 人工确认。OCR 置信度不足、投票不一致、长度异常 → 转人工。
- 禁止：高频重试、多账号并发试码、第三方打码服务绕过（除非用户明确提供并自担风险）。
- 单次登录验证码尝试 ≤ 3 次，每次重新取码。

## 3. 人工确认点（关键动作）

以下动作前必须向用户展示完整内容并获得明确确认，禁止静默执行：

1. 最终提交立案（`PATCH /api/v3/layy/submit`）
2. 删除远端当事人/代理人/材料
3. 使用用户提供的任何第三方凭证

## 4. 礼貌策略

| 项 | 取值 |
| --- | --- |
| 请求间隔 | ≥ 1 秒 |
| 材料上传间隔 | ≥ 3.5 秒（+ 随机抖动 ≤1.5 秒），每 6 份长停 25 秒 |
| 材料上传并发 | 1（跨进程文件锁串行，`--allow-parallel-upload` 也不建议开） |
| 单账号并发 | 1 |
| 失败退避 | 2s / 4s / 8s，最多 3 次 |
| 状态轮询 | ≥ 1 分钟间隔，仅在用户要求时进行 |
| 登录重试 | ≤ 3 次/会话 |

上传是风控最敏感的一段（`签名 → OSS 直传 → 关联槽位`），三步必须整段串行，
不要用多线程/多进程同时上传：那会触发 `OSS 403` 与「获取上传信息失败」，
反而更慢。宁可一次传得久，也不要失败重传。

## 5. 日志脱敏

禁止写入日志：密码（含加密后密文）、token、cookie 原文、身份证号、手机号、完整诉状正文中的个人敏感信息。

允许记录：账号 id、接口路径、HTTP 状态码、业务 code、脱敏后的 message、步骤名、耗时。

错误提示面向用户时必须翻译为可读中文，禁止裸抛 `Mongo E11000`、堆栈、内部字段名。

## 6. 输出免责声明

凡由本技能产生的立案材料整理结果、状态结论、AI 分析，输出时必须附：

> 以上结果由 AI 辅助整理，仅供参考，最终以法院审核意见为准。

## 7. 分发打包要求（提交到技能市场时）

- ZIP ≤ 3MB；目录结构最多两层（`skill-name/SKILL.md`、`skill-name/references/*.md`、`skill-name/scripts/*.py`）。
- `SKILL.md` frontmatter 必填：`name`、`description`、`description_zh`、`description_en`、`version`、`author`。
- 包内不得包含任何真实凭证、测试账号、`.env`、会话持久化文件。
- 提交入口：WorkBuddy 开放平台（open.workbuddy.cn）技能上传；首次需完成开发者认证。
