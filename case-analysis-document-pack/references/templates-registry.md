# 模板来源与登记（本地实战模板包）

**唯一来源**：技能自带 `assets/templates/`（律师实务模板包，43 条登记：32 份 docx + 11 份 .doc 原件，按 10 类子目录存放）。
**没有下载、没有骨架生成、没有联网**。缺模板直接报错，禁止伪造替代文件。

## 目录

```text
case-analysis-document-pack/assets/templates/
  <32 个 .docx>     已脱敏，随仓库分发（status=local_practice）
  _raw/             原始模板包（41 个，含真实当事人信息，已 gitignore，仅本机可用）
```

`_raw/` 里的 12 个 `.doc` 是旧二进制格式，无法无损脱敏，因此**不入库**；
本机运行时仍可用（status=`local_practice_raw_doc`），开源分发后自然缺失。

## 普通版诉状从哪来

`assets/templates/民事起诉状-普通版.docx` 不是脱敏产物，是`scripts/build_complaint_ordinary.py` 从 `_raw/诉状模板(1)(1).doc` 生成的：

- 原文件是空白表单（姓名、证件、金额本来就空），实为 docx 改后缀，可直接改 XML；
- 逐段替换文字、保留原段落样式（仿宋、行距、首行缩进），题名居中，具状人与日期右对齐；
- 当事人信息做成按人分段占位（`{{原告性别段}}` 这类），缺值整段消失，不会留「，族，」断句。

改模板：改 `build_complaint_ordinary.py` 里的 `LAYOUT` 后重跑，不要手改 docx。

## 脱敏规则（占位符化，不是打码）

原包是已办结案件的真实文书。`scripts/pack_templates.py` 把每一个敏感值替换成
**`{{字段}}` 占位符**，不再输出「某某某」「0000」这种无法替换的假数据——
模板里看到 `{{原告}}` 就知道该填什么，渲染时由 `fill_placeholders` 精准替换。

| 原文 | 占位符 |
| --- | --- |
| 当事人姓名（按上下文判角色） | `{{原告}}` / `{{被告}}` / `{{当事人}}` |
| 律师姓名（指派人员、承办人） | `{{承办律师}}` |
| 身份证 18 位 | `{{身份证号}}` |
| 手机号 | `{{手机号}}` |
| 座机（含法院立案庭） | `{{电话}}` |
| 银行卡/账号 16~25 位 | `{{银行账号}}` |
| 案号 | `{{案号}}` |
| 出生日期 | `{{出生日期}}` |
| 详细住址 | `{{地址}}` |
| 公司/个体户 | `{{公司名称}}`（**「类型：有限责任公司」这类勾选项不动**） |
| 律师事务所 | `{{律师事务所}}` |
| 法院名 | `{{受理法院}}` |
| 微信 | `{{微信号}}` |
| 金额（含「（10000）元」） | `{{金额}}` |
| 一般日期（落款/开庭时间） | `{{日期}}` |
| 案由 | `{{案由}}` |
| 民族 | `{{民族}}` |

### 正文块占位

只对案情叙述类文书（强制执行、财产保全、延期开庭、执行结案、线上开庭、撤回保全、要素式执行）启用：

| 模板里的标题 | 整块内容替换为 |
| --- | --- |
| 申请事项 / 申请执行事项 / 执行请求 | `{{申请事项}}` |
| 事实与理由 / 事实和理由 | `{{事实与理由}}` |
| 执行依据 / 执行依据判项主文 | `{{执行依据}}` |
| 案由 | `{{案由}}` |
| 文书号 | `{{案号}}` |
| 生效日期 | `{{日期}}` |

规则：标题原样保留，紧跟的正文第一段变 `{{字段}}`，其余段落清空（保留段落与表格结构）；
遇到「此致 / 申请人 / 时间 / 特此」等 20 字以内落款行即结束块。
情况说明类（立案/现金/其他材料）把「对于…」「本人已依法…」开头的长段落占位成 `{{情况说明}}`。

角色判定：姓名前面最近的关键词是「被申请人/被告/被执行人」→ `{{被告}}`；
「申请人/原告/申请执行人/委托人」→ `{{原告}}`；「指派人员/承办人」→ `{{承办律师}}`；
无关键词 → `{{当事人}}`。

姓名名单由 `load_known_names()` 从 `_raw` 原件抽（「姓名，男/女，X族」「关键词：姓名」
「与被告X」「指派人员：X」等模式），`sanitize` 输出会打印 `known_names`。
**换模板包后要过一眼这份名单**，漏的人名会原样留在正文里。

## 残留（已知）

| 残留 | 原因 |
| --- | --- |
| 正文里的个案事实（金额、具体日期、判决细节） | 属于叙事文本，正则无法可靠切分；需要时由 Agent 改写，不自动占位 |
| 性别 / 民族 | 表单固定词，不含身份信息 |
| 法庭、仲裁委等细粒度机关名 | 只处理「X县/市/区人民法院」 |
| 12 个 `.doc` 原件 | 旧二进制格式无法安全写回，只在 `_raw`（gitignore） |

复现与自查：

```bash
python scripts/pack_templates.py sanitize --raw assets/templates/_raw --out assets/templates
python scripts/pack_templates.py scan --dir assets/templates      # 应输出 dirty = {}
```

`scan` 走同一套规则，改完脱敏逻辑必须重跑；**残留不是 0 就别推仓库**。

## 分类与命名规范

模板按业务流程分 10 类，文件名统一为「文书正式名称（限定词）」：

- 不带序号前缀（分类已承担排序）、不带 `1、`/`(1)`/`- 副本`/`模板` 这类噪音；
- 括号统一全角 `（）`，限定词只写案由、主体或格式差异；
- `.doc` 旧格式只在 `_raw`，文件名同样按此规范登记。

## 只读约束（硬规矩）

**模板不得修改，一律复制副本使用。**

| 层 | 路径 | 权限 |
| --- | --- | --- |
| 源模板 | `assets/templates/` | 只读，脚本永不写入 |
| 工作副本 | `<根>/通用件/模板/` | 复制后 `chmod 444`，Word/WPS 存不进去 |
| 文书产物 | `<案件目录>/04未签稿/` | 可写，全部填充发生在这里 |

```bash
# 查副本是否被改过、是否还只读
python scripts/manage_templates.py --root "<根>" --verify
# 被改过就恢复成源模板（覆盖副本）
python scripts/manage_templates.py --root "<根>" --restore
# 删除/迁移工作空间前解除只读，否则 Windows 删不掉
python scripts/manage_templates.py --root "<根>" --unlock
```

要改模板内容：改 `assets/templates/` 源文件（先 `pack_templates.py sanitize` 重建脱敏集），
再 `--restore` 覆盖已分发副本。**不要在通用件/模板 里手改，改了下一次 verify 就红。**

## 注入方式

| 模板扩展名 | 行为 | manifest `inject_mode` |
| --- | --- | --- |
| `.docx` | 复制原件 → 末尾追加「填写内容（可打印签字）」段 → 替换 `{{占位}}` | `docx_injected` |
| `.doc` | 复制原件 + 另出 `<同名>-填写内容.docx` | `doc_manual_fill` |

`.doc` 走人工填写是硬约束：旧二进制格式无法安全写回，不要为了「自动」去伪造 docx。

## 禁止

- 禁止联网下载模板、禁止生成「骨架模板」冒充正式文书。
- 禁止把 `_raw/` 提交进仓库。
- 禁止在模板里写死某个律所/律师信息当作通用内容。
