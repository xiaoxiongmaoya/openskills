# 文书渲染细节（供改模板/改渲染逻辑时查阅）

本文是 SKILL.md「输出清单」的展开版。日常使用看 SKILL.md 即可；新增模板、调整填充逻辑时按本文核对。

## 诉状模板选择与填充

- 默认用**通用多当事人版** `complaint_general`（`民事起诉状（通用多当事人版）.docx`）。只有律师明确要要素式、且案由有对应模板时才用 `complaint_elements_loan/_traffic/_sale`，否则一律 `complaint_general`。
- 通用诉状是「一人一行」结构：预留 2 行原告 + 2 行被告，行占位符为 `原告N姓名/性别/民族/出生日期/住址/身份证号/电话`、`被告N…`，单值占位符 `案由`/`诉讼请求`/`事实与理由`/`受理法院`。
- **多个原告/被告各占一行**，不得用顿号挤在一行；实际人数少于模板行数时，多余行整段删除（`docx_helper.fill_complaint_rows`），不留“原告：”空行。
- **没有的信息一律留空**：字段为空直接空着，并自动清理空字段留下的多余标点（如“，，”“，住”“案号为。”）；**禁止写“待补/待确认/（待补充）”**，禁止编造。
- 性别、出生日期可**从身份证号推导**（性别=第17位奇偶，出生=第7-14位，格式统一 `1985年11月12日`，不用 `1985-11-12`）；民族无来源就留空（民族值本身已含“族”字，模板里不要再拼一个“族”）。

## 诉请与事实由脚本生成

- `诉讼请求` 骨架固定三条措辞：`1. 判令被告向原告支付拖欠的{X}人民币{N}元；` / `2. 判令被告承担原告为实现债权支出的律师费（以票据金额为准）；`（仅当证据包含律师费支付凭证）/ `3. 本案诉讼费用由被告承担。`。`{X}` 按案由取（劳务→劳务报酬、买卖→货款、借贷→借款本金、租赁→租金、建设工程→工程款、承揽→报酬，默认款项）。前 n-1 条分号、末条句号，编号自动重排，**一条一段**（`docx_helper._expand_multiline_paragraphs` 拆段）。
- `事实与理由` 由 `facts` 时间线自动串成叙事段（`_build_narrative`），剔除内部来源/置信度标注。
- `案由`/`受理法院` 取自 `agent_findings`，法院名自动剥掉“（被告住所地，德阳广汉）”这类内部说明。
- 这三项**禁止被 `complaint_text.json` 覆盖**（脚本强制以规则值为准）；该文件只用于律师微调 `事实与理由`，不得再写诉请/案由/法院。

## 模板填写四条铁律（30+ 份文书通用，出稿前必须满足）

1. **跨 run 占位符必须能填上**。实战模板（法院/律所原件）里 `{{身份证号}}` 常被 Word 拆到多个 run，纯 XML 字符串替换会漏。`docx_helper.fill_placeholders` 已分两阶段：先 run 内替换（保格式），再对残留占位符按段落合并重建（`_fill_split_placeholders`）。
2. **被告段不得串成原告信息**。强制执行/保全/延期开庭等模板的「被申请人」段与「申请人」段共用 `{{地址}}`/`{{身份证号}}`/`{{手机号}}`/`{{出生日期}}` 这类无角色键，直接填会把原告信息写进被告栏。`docx_helper.qualify_role_placeholders` 会把被申请人/被执行人/被告段里的无角色键改写为 `{{被告X}}`；对应键（`被告地址`/`被告身份证号`/`被告手机号`/`被告出生日期`）由 `build_fields` 提供。
3. **内部备注绝不进文书**。`agent_findings` 里的“待律师提供（…）”“见聊天记录（…）”“（备案登记文本）”等说明，统一由 `render_documents._sanitize_fields` 在出稿前剥掉括号说明并清空占位文案；`原告身份信息`/`被告身份信息` 改为从 `party_info` 重建，不再沿用 findings 旧文本。
4. **模板缺失只跳过不崩**。模板包不齐（当前 11 个 key 缺源文件）时，`render_documents` 记入 `manifest.skipped` 并在提交材料清单顶部提示，其余文书照常生成。

## 字段映射层（所有文书共用一份超集）

- `render_documents._expand_aliases` 把同义占位符补齐：`手机号`/`电话`/`联系电话`/`联系手机号码` 同源，`开户行`/`开户银行`、`账号`/`收款账号`/`银行账号` 同源，`当事人` 取原告，邮编/电子邮箱/联行号取自 `party_info` 原始字段。只填空位，不覆盖已填值。占位符用词超出别名的，在 `_expand_aliases` 加一行即可，**不要为新模板另写专用映射函数**。
- 角色称谓表在 `docx_helper._ROLE_ALIAS`：`申请人`/`申请执行人`/`委托人`/`上诉人` → 原告，`被申请人`/`被执行人`/`被上诉人` → 被告。`qualify_role_placeholders` 按段首称谓给该段无角色占位符加前缀。
- `keep()` 过滤空值填写行，并对含换行或不以「标签：」开头的段落整段保留——证据清单、情况说明这类纯文本段落绝不能被逐行解析，否则只剩含冒号的那一行。
- **多当事人自动拆行**：`docx_helper.expand_multi_party_paragraphs` 把「申请人/被申请人/原告/被告」单行段落按实际人数复制成多行，键改写为带序号的 `{{被告2身份证号}}`；字段由 `_expand_aliases` 的 `原告N*/被告N*` 系列提供。

## 追加段落与落款

- 追加段落的取舍：`_emit(append_paras=...)`。模板本身用占位符承载正文的（`enforcement`、`authorization`、`preservation` 系列）传 `False`，否则正文后会重复一整段“填写内容”；只有正文靠表格/空白待填的（`evidence` 证据清单）才保留追加。
- 落款：`具状人`、`年月日` 自动右对齐（`docx_helper._align_signature_right`）。
- `{{日期}}` 统一填 `　　　　年　　月　　日`（全角空格）；开庭日期用独立键 `{{开庭日期}}`，留空待律师填。模板自带横线的（如「____年___月___日」）保持原样不覆盖。
- 落款写法已被 `template_hygiene.py --fix` 统一（原来 11 种写法）。换新模板后先跑 `--scan`，报「落款日期格式不统一」的会被改齐；「出生日期：  年  月  日」属当事人信息栏，不在统一范围内。

## 证据清单

- **自动生成正式目录条目**：读 `05案件信息/evidence_package.json` 的「证明目的」，按 债权凭证 → 身份证明 → 维权费用 → 委托手续 → 其他 归组排序，输出「证据N：xxx」。同一笔支出多张截图（支付成功 + 账单详情、原价 + 优惠实付，差值 <1 元）自动合并，只留实付金额；存疑材料单列「待核实后决定是否提交」。**原始文件名（`企业微信图片_2026….jpg`）绝不进正式目录**。
- **表格可直接填**：在 `06运行记录/complaint_text.json` 写 `"证据清单": [{"名称": "短信欠条截图", "证明内容": "被告确认拖欠工资12000元"}, …]`，脚本按序填进模板表格并删多余空行，**措辞由模型写、位置由脚本管**。写成字符串则按纯文本追加；都不写才用自动条目。模板固定 9 行，超过在清单里提示「需手工加行」，绝不静默丢条。

## 模板净化（换模板或新增模板后必跑）

`python scripts/template_hygiene.py --scan` 体检，`--fix` 修复。规则覆盖：横线上残留的上手人名、写死的性别民族、写死的具体案由、写死的开庭时间法庭。模板来自真实用过的文书，不清就等着把别人案子印进自己文书。识别靠正则模式，不依赖姓名黑名单，因此能发现 `check_sensitive.py` 名单外的历史当事人。

## 回归自测

改任何渲染逻辑后必跑：`python scripts/selftest.py --case-dir <案件目录>`。内容：33 份 docx 模板逐个实填压测（断言无 `{{...}}` 残留、无 None、无「族族」「案号为。」残句、被告段不含原告身份证号）+ 四份主文书渲染复核。退出码非 0 即失败，修完再提交。
