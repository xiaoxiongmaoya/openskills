# 已知坑（改渲染逻辑前先看）

每条都是实战踩过的坑，对应代码里已落地防御。改动渲染/填充逻辑时逐条核对，别把防御删了。

## 1. 跨 run 占位符填不上
Word 常把 `{{身份证号}}` 拆到多个 run（拼写检查、字体切换都会触发），纯 XML 字符串替换会漏。
防御：`fill_placeholders` 两阶段——先 run 内替换，再按段落合并重建。
**改模板后必须验证「无 `{{...}}` 残留」**（selftest 已覆盖）。

## 2. 被告栏串进原告信息
保全/执行/延期开庭等模板里「被申请人」段与「申请人」段共用 `{{地址}}` 这类无角色键，
直接填会把原告身份证号写进被告栏，文书直接作废。
防御：`qualify_role_placeholders` 按段首称谓把无角色键改写为 `{{被告X}}`。

## 3. 内部备注写进文书
findings 里的“待律师提供（…）”“见聊天记录（…）”一旦被占位符带进文书就是事故。
防御：`_sanitize_fields` 出稿前剥括号说明 + 清占位文案；身份段落从 `party_info` 重建。

## 4. 「汉族族」
民族值本身含“族”（“汉族”），早期模板写 `{{民族}}族`，拼出“汉族族”。
防御：值统一存含“族”的写法，模板里不拼；`_clean_empty_tails` 加了 `族{2,}` → `族` 兜底。

## 5. 「案号为。」空值残句
案号留空后模板残句变成“案号为。”。防御：`_clean_empty_tails` 清理
`[，,]?\s*案\s*号\s*为?\s*(?=[。；，,])` 这类空键残句。新增空值字段时同类残句照此处理。

## 6. 字符串 replace 定位相同空行会全部命中第一行
模板里有多个相同空段/相同占位行时，用整段文本做 `str.replace` 会把所有出现处一起改掉
（比如想只改第二处）。docx_helper 里按段落逐个定位处理，不要引入整文档 replace 的捷径。

## 7. 按需文书的事由答非所问
extra 申请书的 `事实与理由` 曾直接继承诉状案情复述（答的是「谁欠谁钱」，
不是「为什么要保全」），律师得整段重写。
定调：**理由一律留空，不给默认理由**——模型/律师没写就留空，清单列「需补写事由」。
清单只提示**实际生成出来**的文书（模板缺失被跳过的不提，否则清单指向不存在的文件）。

## 8. keep() 把纯文本段落当「标签：值」截断
证据清单、情况说明这类多行纯文本段落，若逐行按「标签：值」解析，只剩含冒号的那一行。
防御：`keep()` 对含换行或不以「标签：」开头的段落整段保留。

## 9. 证据目录表格静默丢条
模板表格固定 9 行，证据超过行数时直接填会丢条。
防御：`fill_evidence_table` 返回实填数，溢出记 `evidence_overflow` 并在清单提示「需手工加行」。
